# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Add durable project-specific notes here as they are discovered through real work.

## Runtime

- Needs Python 3.11+ (see `pyproject.toml`). The system `python3` on this Mac is 3.9, which cannot evaluate the `str | None` annotations in the pydantic models and fails at import. Build the venv with `python3.12`: `python3.12 -m venv .venv`.
- Dev server: `.venv/bin/python -m uvicorn backend.app:app --host 127.0.0.1 --port 8766`. Native app: `desktop.py` (pywebview); `FM_COCKPIT_NO_WINDOW=1` starts the server only, prints readiness, then exits.

## Auth

- Sign-in is file-based (`backend/auth.py`): a plaintext `~/.firstmate-cockpit/credentials` (path overridable via `FM_CREDENTIALS_FILE`), created with defaults on first run. Sessions are signed with a persistent key using stdlib `hmac` only - deliberately no `itsdangerous`/JWT dep so the py2app bundle stays simple.
- All `/api/*` (except login/logout/auth-status/health) and both websockets are gated by a signed cookie. `/` and `/static/*` stay public so the page can serve the login screen and handle 401s itself.

## Open PRs across the fleet (`/api/open-prs`)

- `backend/openprs.py` walks `$FM_HOME/projects/*`, reads each clone's `origin` remote, and lists every OPEN PR per forge. GitHub uses the operator's authed `gh` CLI; Bitbucket hits the REST API with the cached git credential from `git credential fill`. Result is cached ~60s (`_TTL`); a clone with no remote / no usable credential is skipped, never failing the endpoint.
- Bitbucket gotcha: the cached credential's username (a bare Bitbucket handle like `manjeshp`) is rejected by the REST API when the stored password is an Atlassian API token - the token must be paired with the account **email**. `_bb_candidates()` therefore tries the credential username first, then falls back to `git config --global user.email`, and memoizes whichever works.
- The dashboard merges these with active-work PRs (dedupe by url in `mergedPRs()` in `index.html`); work PRs keep the Merge affordance, forge-only PRs get a Review button that opens the PR on its forge.

## Front-end: the "Helm" UI (`backend/static/index.html`)

- The whole UI is one self-contained file (system fonts, inline SVG, vendored JS, no CDN - keeps the py2app bundle simple). It is the "Helm" instrument-panel redesign: a nav rail, a top bar with a one-click target switcher + theme menu, and four views - **Fleet** (decision-first dashboard: answer banner that goes calm/loud, Needs-you, In flight, Ready to merge, quiet readouts incl. the watcher-health signal), **Console**, **Review** (open PRs grouped by forge), **Settings**. App view/tab state lives on `#app` (`dataset.view` / `dataset.tab`).
- **Themes are OKLCH tokens with a hard WCAG-AA gate.** A curated set of dark + light themes (`:root[data-theme="..."]` blocks). `scripts/verify-contrast.mjs` is the **single source of truth**: `node scripts/verify-contrast.mjs verify` converts OKLCH -> sRGB -> WCAG luminance and fails if any key text/UI pair (incl. pill-text-on-tint and icon-on-solid-amber) is < 4.5:1; `... css` re-emits the exact token blocks pasted into `index.html`. Change a theme colour there, re-run the gate, re-emit. AA is an acceptance gate, not a nicety.
- The "needs you" **amber** is built entirely from each theme's own `--need` / `--need-ink` tokens (not one fixed hue), so the attention banner harmonises with every theme while still reading loud. Legacy `localStorage['fm-theme']` ids migrate to the default (`helm-dark`).

## Console: Terminal + Shell (xterm.js, one view, two tabs)

- Terminal and Shell are merged into one **Console** view with two tabs: **Live terminal** (`⌘2`) and **Shell** (`⌘3`). Both are real xterm.js; the fit/focus/reconnect guards key off `termVisible()` / `shellVisible()` (view===console && the active tab). All existing wiring is preserved: search, A−/A+ zoom, independent terminal palette, copy, jump-to-bottom, auto-reconnect, and the captain composer (`/api/send`) on the live tab.
- The live terminal attaches to a per-connection *grouped* tmux mirror (`backend/terminal.py`). The group name carries a per-connection suffix (`cockpit_<session>_<pid>_<hex>`) so two cockpit instances don't fight over one shared mirror and kill each other's attach (that showed up as a dead `[exited]` frame). When the inner tmux client exits, the bridge closes the socket so the frontend auto-reconnects.
- The Shell tab is a genuine `pty.fork()` login shell (`backend/shell.py`, `/ws/shell`, same auth gate as `/ws/terminal`), so lines that scroll off the top land in xterm's scrollback. The scrollback win is **primary-screen only**; the shell's wheel handler is conditional (`initShell`): native xterm scroll while `shTerm.buffer.active.type==='normal'`, PageUp/PageDown only when `'alternate'`. The mirror tab hijacks the wheel to PageUp/PageDown unconditionally (it is always alt-screen).
- Light-terminal readability (`matchAppTheme`/`applyTermTheme`): the first mate emits much output as **truecolor (24-bit)**, which the ANSI palette can't remap - so xterm's `minimumContrastRatio` is raised to 4.5 (`contrastFloorFor()`) whenever the terminal bg is light by WCAG luminance, darkening *any* foreground to meet contrast; dark terminals keep it at 1 (off). App tokens are OKLCH, but xterm needs concrete colours, so `cssColorToHex()` converts the current theme's `--term-bg`/`--ink`/`--accent`/`--muted` to hex before handing them to xterm.
- **Vendored xterm** (`backend/static/vendor/`, all self-contained UMD, no CDN): scoped `@xterm/xterm@5.5.0` (global `Terminal`), `@xterm/addon-fit@0.10.0` (`FitAddon.FitAddon`), and `@xterm/addon-webgl@0.18.0` (`WebglAddon.WebglAddon`). WebGL is loaded via `loadWebgl()` after `term.open()` with an `onContextLoss(() => dispose())` fallback so a lost WKWebView GL context degrades to the DOM renderer. Both terminals set `smoothScrollDuration:110` for native-feel scrolling. If you bump the core, re-match the addon versions (byte-compare against `npm pack`).
- Image/screenshot paste-into-agent needs no cockpit code: xterm forwards a browser paste as a **bracketed paste** (`ESC[200~…ESC[201~`) over the socket to the PTY, and the agent reads the shared macOS system clipboard for the image. Both tabs share the `term.onData -> ws.send` wiring, so paste works identically in either - do not touch that wiring.

## Native app (`native/`, Swift + SwiftTerm)

- A separate, growing native macOS surface that will eventually replace the web terminal. **It does not touch `backend/` or `desktop.py`** - keep them independent. Build with `swift build` / run with `swift run` from `native/` (Command Line Tools only, **no Xcode / `xcodebuild`**). SwiftTerm is pinned in `Package.resolved` (1.15.0); first build is ~90s. Full run + captain-validation steps live in `native/README.md`; the authoritative design + verified API shapes are in `data/cockpit-native-design-scout/report.md` (sections 3, 4.3, 5, 6, 7, 9).
- **The console** (`main.swift` -> `ConsoleController`) hosts a **dynamic tab collection**, not a fixed two-tab enum. Tabs are `[TabModel]` (`TabModel.swift`), each owning a `CockpitTerminalView` + a `TabLaunch` (re)start recipe, rendered as `TabChipView` chips in a growing tab bar. Supports **new** (`⌘T`/`+`), **duplicate** (`⌘D`, re-runs the same argv), **rename** (double-click / `⌘⇧R` / right-click, name is per-tab and never touches the process), **close** (`⌘W`; closing the last tab opens a fresh shell so the window is never empty), and `⌘1`…`⌘9` select. Tab ops are on the **Tab** menu; zoom+theme on **View**. `ConsoleController.openFirstmateHost()` opens the built-in Shell + Mirror pair; `loadView` calls it at startup so the app still lands there by default, and it is also the pinned Hosts-sidebar entry's connect action (see below). This is Phase 0 of the connection-manager work (design: `data/cockpit-ssh-manager-research/report.md`, Section A4/A5 + D Phase 0). Later phases add the dashboard + embedded backend (P3) and packaging/signing (P4); the console stays backend-free.
- **Navigation shell.** `AppShellController` is the window's root: a fixed, always-visible `IconRailController` (~60pt, icon-only - overview/grid, hosts/server-rack, console/terminal, review/git-branch, settings/gear, avatar) on the left, and to its right a `TopBarController` (destination title, the Search pill with its ⌘K badge, and the theme-picker button) above a body area. The body holds all five destinations (`.overview`, `.hosts`, `.console`, `.review`, `.settings`) as permanent children with only `isHidden` toggled - never rebuilt - so navigating away never tears down `ConsoleController`'s running tabs. **`.hosts` and `.console` are decoupled destinations** (cockpit-native-ui-fixes2): `HostsSidebarController` and `ConsoleController` are each a standalone full-size body view, not panes of a shared `NSSplitViewController` - Console shows just the tab strip/terminal, and Hosts is reachable on its own rail icon exactly like Settings. Connecting a host (`HostsSidebarController.onConnect`/`onConnectPinned`, wired in `main.swift`) opens the ssh/Firstmate tab in `ConsoleController` and then calls `AppShellController.show(.console)` so the new tab is actually visible. `.overview` shows `FleetController` (see below); `.review` is still a `PlaceholderViewController` stub (no native PR-review UI yet); `.settings` shows `SettingsController` embedded directly (not a separate window).
- **Fleet dashboard (`FleetController.swift` + `FleetData.swift`, cockpit-native-ui-fixes2).** The `.overview` rail destination is a real port of `backend/fleet.py`'s `snapshot()` and `backend/openprs.py`'s `open_prs()` into Swift - greeting header, calm/loud answer banner, stat tiles (working/ready-to-merge/queued/done/projects/watcher), an "In flight" list of working crew, and a "Ready to merge" list of open PRs with Review/Merge actions. **No embedded backend**: `FirstmateHome.swift` resolves `$FM_HOME` the same way `backend/config.py` does, then `FleetData.swift` reads `data/projects.md` / `data/backlog.md` / `state/*.meta` directly and shells out to `bin/fm-crew-state.sh` per task (the same authoritative, non-tailed state read the Python backend uses) and to `bin/fm-pr-merge.sh` for the Merge action; `OpenPRsSource` walks `$FM_HOME/projects/*` and re-implements `openprs.py`'s remote-parsing + `gh pr list` + Bitbucket-REST logic natively. `FleetController.refresh()` runs this whole pipeline off the main thread and re-renders on completion - there is no live websocket push (unlike the web app), only a refresh on `viewWillAppear` plus a manual refresh button.
- **Hosts / SSH connection manager (Phase 1, `data/cockpit-ssh-manager-research/report.md` A2/A3, C1, D Phase 1).** `HostsSidebarController` (Termius-proportioned, 220-260pt, list, per-host SF-Symbol icon + Helm accent, quick-connect, add/edit/delete) is its own rail destination (see above); Add/Edit Host is a dedicated full-page window (`AppDelegate.presentHostEditor`), not a sheet on this narrow panel - `HostsSidebarController.onAddOrEdit` forwards the request up through `AppShellController` to the app delegate, which owns `HostEditorController` and the host store. Row zero is always a pinned, non-deletable "Firstmate" entry (anchor icon) whose connect action is `ConsoleController.openFirstmateHost()` - it has no backing `Host` record, so `HostsSidebarController`'s private `HostListRow` enum carries a `.pinned` case alongside `.header`/`.host`. A saved `Host` (`Host.swift`) is `Codable` and persisted by `HostStore` to `~/Library/Application Support/FirstmateCockpit/hosts.json` (override `FM_HOSTS_FILE`) - the native app's first on-disk persistence. **Secrets stay off disk:** `Host.password` is excluded from `CodingKeys` (session-only, memory); the only persisted credential is `keyID`, a reference into the Phase 2 key store below - never a path or key material. **Connect** = `ConsoleController.openSSH(...)` adds a `TabLaunch.ssh` tab running `/usr/bin/ssh` with the host's argv (the C1 drop-in) plus, when `keyID` is set, a `-i <path>` resolved fresh on every start (see below); the tab takes the host label + accent, and Phase-0 duplicate re-runs the same launch (re-resolving the key) for a second session. Quick-connect parses `[user@]host[:port]` via `HostCatalog.parseQuickConnect`; the Hosts menu's Quick Connect routes through `AppShellController.revealHostsQuickConnect()`, which selects the Hosts destination before focusing it. The topbar Search control is unrelated to Hosts now - see "Find" below.
- **SSH keychain (Phase 2, `data/cockpit-ssh-manager-research/report.md` A1, C3, D Phase 2).** `SSHKey.swift` is non-secret metadata only (label, type, derived public key, fingerprint, certificate), persisted by `SSHKeyStore` to `keys.json` (override `FM_KEYS_FILE`) exactly like `HostStore`. Private key bytes and passphrase live **only** in the macOS Keychain (`KeychainKeyStore.swift`: `SecItemAdd`/`SecItemCopyMatching`/`SecItemDelete`), each item's `SecAccessControl` requiring Touch ID (falling back to the device passcode where biometry isn't enrolled) and `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` (never iCloud-synced). Generation and PEM/OpenSSH import both shell out to `/usr/bin/ssh-keygen` (`SSHKeyGenerator.swift`) rather than reimplementing the OpenSSH key format or its passphrase KDF - `.ppk` files are detected and rejected with a conversion hint, not parsed. `SSHKeyStore.addNew(_:privateKeyData:passphrase:)` is the one path that writes a brand-new key (Keychain first, then metadata) - both the Keys screen and the host editor's inline "+ New Key…" popup entry (`HostEditorController.presentNewKeySheet`, still a sheet - now on the host editor's own window rather than the sidebar's) go through it, so a new key can be created without leaving the host form. At connect time `SSHKeyMaterializer.materialize` does the one Keychain read (the Touch ID prompt) and writes a private `0600` temp file for `ssh -i`; `ConsoleController.connectSSH`/`cleanupSSHKeyTempFile` own its lifecycle (fresh file per tab start/reconnect, deleted on close/exit/quit). The "SSH Keys" browser (`KeysSidebarController.swift` + `KeyEditorController.swift`) is a separate window (Keys menu, `⌘⇧K`/`⌘⇧N`), not a rail destination. Known caveat: an unsigned `swift build`/`swift run` binary has no stable code-signing identity, so Keychain access can prompt again (or rarely fail to re-read) across rebuilds - resolves once the app is signed (Phase 4).
- **Power features (Phase 3, `data/cockpit-ssh-manager-research/report.md` B1/B2/B4/B5, D Phase 3).** All additive `ssh` argv or extra `Host` fields, never new transport code. Jump hosts: `Host.jumpVia` (a saved host's label or a raw `user@bastion`) resolved and chained by `HostCatalog.proxyJumpChain` into `-J a,b,c`. Agent forwarding: `Host.agentForward` -> `-A` (the system agent's `SSH_AUTH_SOCK` is already inherited via `childEnvironmentDict`). Known-hosts prompts: no code needed - `connectSSH` never overrides `StrictHostKeyChecking` and nothing filters the ssh tab's PTY output, so they render like any other terminal output; verified by inspection, not a UI. Groups/tags: `Host.group`/`Host.tags` (present since Phase 1) now drive sidebar section headers and a tag-chip filter row in `HostsSidebarController`. Port forwarding: `Host.portForwards: [PortForwardRule]`, edited via `PortForwardingController` as a sheet on top of `HostEditorController` (a window since the nav-redesign task, not a sheet itself - see above), turned into `-L`/`-R`/`-D` flags. Snippets: `Snippet`/`SnippetStore` (mirrors `HostStore`), managed from `SnippetsController` (Snippets menu, `⌘⌥N`/`⌘⌥P`); Run sends text+Enter to the active tab via `TerminalView.send(txt:)`; a host's `startupSnippetID` fires the same way ~1.5s after ssh starts (best-effort, no "shell ready" signal exists to hook). Session logging: `CockpitTerminalView` overrides SwiftTerm's `dataReceived(slice:)` to tee raw bytes to a `FileHandle` under `~/Library/Application Support/FirstmateCockpit/logs/` - deliberately not SwiftTerm's own `setHostLogging(directory:)`, which splits output across one file per read syscall rather than a single transcript. Toggle via `⌘⇧L`/toolbar icon, or default-on via `FM_LOG_SESSIONS_DEFAULT=1`.
- Every tab is a `CockpitTerminalView` (the P1 paste-hardening `LocalProcessTerminalView` subclass - do not touch its paste override; it is what makes screenshot-paste-into-Claude work). Terminals fork their child **in-process** via `startProcess`, so there is no websocket byte-pump and no per-keystroke round trip.
- **Scrolling:** SwiftTerm 1.15's `scrollWheel` already scrolls normal-screen buffers smoothly and content-wise (accumulates precise trackpad deltas -> whole lines 1:1, no page-jumps; `scrollSensitivity` default 1.0), so shell tabs feel like WezTerm with no extra code. Each terminal gets a **10,000-line scrollback** via `term.terminal?.changeScrollback(...)` (SwiftTerm default is 500). The Mirror tab is tmux on the alt-screen and pages inherently - do not try to force smooth-scroll there.
- The Mirror ports `backend/terminal.py`'s grouped-session lifecycle to Swift `Process` (`TmuxMirror.swift`): same `new-session -d -s <group> -t <session>` / `select-window` / `window-size latest` / `status off` / teardown, same `cockpit_<sess>_<pid>_<hex>` naming. Target is `FM_MIRROR_TARGET`, then Settings > General's "Mirror target" (`AppSettings.mirrorTarget`), default `firstmate`. A crash (not a clean quit) can leave a stale `cockpit_*` group, same tradeoff as the Python version. **Known follow-up:** `setUp` only calls `select-window` when the target names one explicitly (`firstmate:<N>`); with just a session name it inherits whichever window was active in the real session at that instant, so if that happens to be something other than the first-mate pane (e.g. a herdr TUI), the mirror shows that chrome instead. Pin `firstmate:<N>` until there's a real fix - see the doc comment on `TmuxMirror.setUp`.
- **`HelmTheme.swift` holds all 8 Helm palettes as concrete sRGB hex** (Helm Dark/Light hand-pinned; Midnight/Graphite/Nocturne/Paper/Frost/Linen derived at load time by `HelmTheme`'s own OKLCH->sRGB conversion, mirroring `scripts/verify-contrast.mjs`'s math, from the same OKLCH tokens as `backend/static/index.html`'s `:root[data-theme=...]` blocks - the ANSI reds/greens/yellows are shared with `dark`/`light` since those tokens barely change per theme; only accent-linked ANSI slots and the chrome/cursor colours are re-derived). If a token changes in the web CSS, update the matching tuple in `HelmTheme`'s `derived(...)` calls. **`ThemeManager.swift` is the single source of truth for which of the 8 is active**, persisted by `HelmTheme.id` (migrates a pre-nav-redesign "fm.themeMode" dark/light pref once) - `ConsoleController` and every other theme-aware window/view (`HostsSidebarController`, `KeysSidebarController`, `SnippetsController`, `IconRailController`, `TopBarController`, `SettingsController`, `PlaceholderViewController`, `FleetController`) call `ThemeManager.shared.observe { ... }` rather than tracking their own copy. A window/view using `NSVisualEffectView` (or plain semantic system colors) needs its `appearance` forced to `.darkAqua`/`.aqua` in that observer for its colors to resolve against the Helm mode instead of macOS's own light/dark setting - `SettingsController` needed this added when it moved from its own floating window into the shared, always-themed body area (nav-redesign task). `ThemeMenu.swift` builds the shared DARK/LIGHT-grouped, swatch + checkmark `NSMenu` used by both the topbar's theme button and Settings' Appearance row.
- **`AppSettings.swift` + `SettingsController.swift` (⌘, / App menu > Settings…, or the rail's gear icon) are the native Settings panel** - three cards, matching the web app's Connection/Appearance/Terminal visual weight (icon + title headers, generous spacing, no Sign-in card - native has no login): **Connection** (mirror-target field + a live `TmuxMirror.listSessions()` session-picker of selectable cards, plus the working-directory chooser); **Appearance** (the 8 `HelmTheme.allThemes` as a DARK/LIGHT-grouped wrapping grid of preview cards - swatch bars + name + checkmark - built by `SettingsController.rebuildAppearanceGrid`, the same source of truth `ThemeMenu` uses for the topbar picker); **Terminal** (font-size presets 12/13/14/16 via `ConsoleController.stepFontSize`, plus three `NSSwitch` toggles: "Reconnect automatically" - `AppSettings.autoReconnect`, read by `ConsoleController.processTerminated` to actually re-run a dropped tab's launch after a short delay instead of only showing the ⌘R hint; "Bell & notifications" - `AppSettings.notifyOnNeedsDecision`, driving `FleetNotifier`'s background poll of `FleetDataSource.parseTasks()` to post a real macOS notification the first time a task newly needs the captain; and session-logging-by-default, moved here from the old General section). `FM_SHELL_CWD`/`FM_MIRROR_TARGET`/`FM_LOG_SESSIONS_DEFAULT` env vars still win when set, `AppSettings` (backed by `UserDefaults`) is the fallback.
- **Find (Fix 4, cockpit-native-ui-fixes2).** The topbar Search pill / its ⌘K calls `AppShellController.activateConsoleFind()`, which brings Console forward and calls `ConsoleController.showFind()` - the exact same in-terminal find the console toolbar's own magnifying-glass icon triggers (SwiftTerm's native find bar on the active tab). There is one search behavior in the app, not two; it has nothing to do with Hosts.
- **Two app bundles live under `dist/` (gitignored) and are easy to confuse.** `dist/Firstmate.app` is the old web/WKWebView app (`backend/` + `desktop.py`, built by the root `build_app.sh` via py2app). `dist/New-Firstmate.app` is this native Swift cockpit, built by `native/build_native_app.sh` (plain `swift build -c release` + manual bundle assembly, no py2app, unsigned, bundle ID `com.firstmate.cockpit.native`). Check the name before opening either.
